### Key Architecture Facts (MUST read before any indicator work)

1. **Per-panel params key on instance `id`, not `indKey`.** `indKey` = tool TYPE; `id` = tool COPY. Duplicates share indKey but have unique ids. `getMergedToolParams(panelIdx, id)` resolves `id`→instance, with a backward-compat fallback for legacy indKey callers (singletons like lingua/curltrend still pass indKey — they work).

2. **`toolMap` in indicators.ts is indKey-keyed → holds only ONE instance (last wins).** For ANY duplicate-able tool, iterate `toolOverrides` instead. Pattern (see emacloud/db_72_89 in indicators.ts):
   ```ts
   if (toolOverrides) for (const t of toolOverrides) {
     if (t.indKey !== 'emacloud') continue
     ensureEMA(Number(t.params?.fast) || 9)
   }
   ```

3. **`toolOverrides` in ReactChartPanel merges per-panel params for ALL tools** — built once per frame via `panelParams[panelIdx]?.[t.id]`. Read merged params from there in dispatch.

4. **`drawEMABand` skips gap/warmup bars via `null == t[e]`.** `null == NaN` is FALSE. So EMA arrays fed to it MUST be `(number|null)[]` with null for warmup/gaps. The shared `ic.ema[N]` cache (from `calcEMA` in indicators.ts) is already null-correct — USE IT. Never compute EMAs inside a render function. EMA Cloud (`44ff5dd`) is the reference implementation.

5. **Catalog `params` are cosmetic until WIRED** into both (a) indicators.ts ensure*() and (b) the ReactChartPanel dispatch. Verify with the dev bands fix.
